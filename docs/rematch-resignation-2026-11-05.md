# Rematch, resignation and spectator verification

Sender navigation used to live in `ChallengeMenu`, which was absent from rematch buttons. Signed-in app shell tracking now follows sent invitations across all board games; rematch buttons and the profile menu register the created invitation. IDs are remembered per user in session storage. Only tracked accepted games trigger navigation, and stale/closed IDs are removed. Refreshing an already-finished board can recover an accepted rematch using the authoritative active invitation and old board status. Generic waiting/in-progress polling remains a one-second fallback.

The three board routes key their clients by match ID to reset old board/rematch state. Shared `resignMatch` owns participant authorization, locking and idempotent settlement; each game publishes status and result reason. Chess applies the action response immediately, fetches the final result ledger without refreshing the whole page, and continues a slow finished-board snapshot poll. Its props initialization effect no longer runs when live status changes, preventing an older page snapshot from undoing a live result. Tic-Tac-Toe and Connect Four show reason-specific result descriptions. Modal focus restoration avoids scrolling, and a stable scrollbar gutter reduces horizontal layout changes.

Spectator HTTP regressions cover all three games: an outsider can observe an active game, is recorded in the spectator list, receives a terminal status, and cannot send a chess game action. Existing server integration tests also cover outsider resignation/moves and duplicate resignation. This verifies API behavior, not a claim that a two-browser graphical spectator session was manually completed.
