# Game Engine & Database Audit Report

I conducted a deep-dive review across all **14 game components**, their **procedural generators**, and their **master database schemas** to identify any mismatches where games might be ignoring the database or failing to scale in difficulty. 

Here are the results of the audit:

## 🟢 The Good News (Perfectly Matched)
These games are perfectly wired. The React component correctly reads the dynamic data generated by the backend, meaning they properly scale in difficulty and pull from the database exactly as intended:
- **Trivia** (Uses `master_trivia_bank`)
- **Missing Letters** (Uses `master_word_bank`)
- **Word Unscramble** (Uses `master_word_bank`)
- **Target Number** (Procedural math generation)
- **Mental Math** (Procedural math generation)
- **Logic Sequence** (Procedural logic generation)
- **Sudoku** (Procedural grid generation)
- **Memory Challenge** (Procedural string generation)
- **Speed Typing** (Uses `master_typing_bank` — *Fixed today*)

## 🔴 The Bad News (Major Mismatches Found)
I found **three** games that are currently disconnected from the database or backend logic in some way. 

### 1. Spot the Imposter (Odd Object Game)
- **The Issue**: The database (`master_odd_object_bank`) was seeded with **Text Words** (e.g., Theme: "Colors", Items: ["Red", "Blue", "Green"]). However, the frontend UI for this game was built exclusively to render an **Emoji Grid**. Because text words are too large to fit in the grid squares, the frontend completely ignores the database and falls back to a hardcoded array of emojis (`TRICKY_PAIRS`). 
- **The Result**: The game ignores the database entirely and repeats the same hardcoded emojis.
- **The Recommended Fix**: We need to wipe the `master_odd_object_bank` and re-seed it with Emoji themes (e.g., Theme: "Fruits", Items: ["🍎", "🍐", "🍊"]) so the UI can render them properly.

### 2. Concentration (Card Match Game)
- **The Issue**: The backend generator properly creates a memory grid that scales with difficulty (Easy = 8 cards, Medium = 12 cards, Hard = 16 cards) and passes it to the frontend. However, the frontend component ignores this data and forces a hardcoded 12-card grid using its own internal emoji list. 
- **The Result**: The game never gets harder or easier; it is permanently stuck on "Medium" difficulty, and it ignores the backend.
- **The Recommended Fix**: Update `CardMatchGame.tsx` to read the cards passed from the backend instead of generating its own.

### 3. Bug Hunt (Coding Game)
- **The Issue**: The database contains a `master_coding_bank` table, but the backend generator ignores it. Instead, the generator uses a hardcoded list of 10 code snippets hidden inside the code (`game-content.ts`).
- **The Result**: You cannot add new coding questions via the Supabase database because the game isn't looking there. It will just repeat those 10 hardcoded snippets.
- **The Recommended Fix**: Rewrite `generateBugHunt` to query the `master_coding_bank` table just like the other games do.

*Note: Games like Reaction Speed and Stroop Effect were not included as they are purely client-side reflex tests and do not use database questions.*
